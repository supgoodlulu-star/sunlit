# 물고기 크기 + 기존 판매함 가격 연동 — 0.8.15

Minecraft 1.20.1 / Forge 47.4.0 / Java 17. Society Sunlit Valley 4.1.5A의 Stardew Fishing 3.7 / Aquaculture 2.5.7 / Quality Food 2.4.3 및 KubeJS 판매함 코드를 기준으로 연결했습니다.

## 설치

1. 서버와 모든 클라이언트를 종료하고 기존 sunlit-journal-core JAR를 제거합니다. Reforged dev.8과 글꼴 보정은 그대로 둡니다.
2. Sunlit_Fish_Sizes_Install.zip의 mods와 kubejs 폴더를 모드팩 폴더에 합칩니다. 새 수첩 JAR는 sunlit-journal-core-0.8.15-fish-sizes.jar입니다.
3. kubejs/startup_scripts/sunlit_fish_size_shipping.js가 추가됐는지 확인합니다. 기존 모드팩의 globalShippingBinHandlers.js를 지우거나 교체하지 않습니다.
4. 서버와 클라이언트를 완전히 재시작합니다. startup 스크립트 추가는 /reload만으로 적용되지 않습니다.

JAR만 교체하면 크기 정보는 생기지만 판매함 배율은 적용되지 않습니다. 판매함 스크립트도 함께 설치하세요. 원래 Society 판매함 계산 함수가 없는 별도 모드팩에는 해당 스크립트를 설치하지 않습니다. 어종별 길이 설정 데이터팩은 선택 사항입니다.

## 적용 규칙

| 크기 | 확률 | 판매 배율 | 기준 길이 대비 |
| --- | --- | --- | --- |
| 작은 개체 | 20% | ×1 | 0.5배 이상 0.8배 미만 |
| 보통 개체 | 60% | ×1 | 0.8배 이상 1.2배 미만 |
| 큰 개체 | 17% | ×1.3 | 1.2배 이상 1.8배 미만 |
| 초대형 | 2.8% | ×2 | 1.8배 이상 3배 미만 |
| 초거대 | 0.2% | ×3 | 3배 이상 5배 미만 |

크기는 서버에서 낚시 보상 생성 시 한 번만 저장합니다. 길이는 0.1cm 단위입니다. 어종별 기준 길이 79개는 게임용 설정이며 생물학적 실측값이 아닙니다. 예: 피라미 8cm / 잉어 60cm / 참치 150cm가 기준 길이입니다. 추가 모드의 fishes 태그 물고기도 지원하며 별도 기준이 없는 어종은 기본 40cm를 사용합니다.

기존 낚시 스킬은 보상 스택 단위로 추가 지급을 처리합니다. 기존 지급 수량이 바뀌지 않도록 보상 묶음을 쪼개지 않습니다. 같은 보상 묶음이나 그 묶음에서 기존 스킬로 복제된 물고기는 같은 길이·크기 기록을 공유합니다. 서로 다른 낚기에서 얻은 크기/포획 정보가 다른 물고기는 한 슬롯에 겹쳐지지 않습니다.

기존에 보관하던 물고기, 양식장 등 낚시 이외의 경로로 만들어진 일반 물고기는 임의로 크기를 붙이지 않으며 기존 가격을 유지합니다. 이 기능은 물고기 아이템의 길이 기록이며 월드 속 물고기 몹의 모델 크기를 변경하지 않습니다.

툴팁에 길이·크기·판매 배율·낚은 사람을 표시합니다. /자랑하기와 [아이템]의 실제 아이템 호버에도 표시됩니다. 서버 저장 형식은 전용 sunlit_fish_size 태그이며 기존 품질·이름·인챈트·외부 NBT를 보존합니다. 거래/보관/재접속 시 같은 아이템의 기록은 유지됩니다.

판매함은 어종의 기존 가격, 별 품질, 판매 속성/스킬, 어종별 특수 보너스를 원래 함수로 먼저 계산한 뒤 크기 배율을 곱합니다. 추가 금액은 SUN 최소 단위로 반올림합니다. 작은 개체·보통 개체·기존 물고기 가격은 줄이지 않습니다. 판매 미리보기, 일반 판매함의 나중 제거 슬롯 목록, 스마트 판매함의 즉시 제거, 판매 불가 아이템 처리도 기존 로직을 사용합니다. 코인 전환/지급·출금·보관함 블록 동작은 교체하지 않습니다.

개인 어종별 최대어 기록은 실제 보상이 지급된 뒤 갱신합니다. 단순 보상 추첨이나 실패한 미니게임에는 기록을 부여하지 않습니다. 기록 경신은 개인 채팅으로 알리고, 초거대가 개인 기록을 경신하면 전체 채팅에도 알립니다. 기록은 기존 플레이어 영구 데이터 아래 별도 항목으로 저장하며 기존 사망 복제 처리도 유지합니다. 어종 ID가 바뀌는 요리/가공 결과에는 생선 크기 판매 배율을 적용하지 않습니다.

## 어종 길이 편집

동봉한 fish_size_profiles.json은 data/sunlit_journal_core/fish_size_profiles/default.json으로 사용합니다. 선택 사항인 sunlit_fish_lengths.zip을 월드 datapacks에 넣고 내부 JSON을 수정한 뒤 /reload 하세요. 단위는 cm이며 새로 잡는 물고기부터 반영됩니다. 기존 물고기의 저장된 길이·크기는 다시 뽑히지 않습니다. 확률·가격 배율은 이번에 합의한 값으로 고정했습니다.

꿈방울 가격·잠재옵션·승급·업무 보상·SUN 코인 기준은 변경하지 않았습니다. 수첩의 기존 5개 탭과 채팅 장식도 유지합니다.

검증 범위와 실제 캡처는 TEST_RESULTS.md 및 validation/fish-sizes-0.8.15 참조. 관련 모드 및 원본 판매 계산 함수로 검증했으며 사용자 전체 모드팩의 실물 판매함 블록/코인 수령이나 Essential 원격 2인 접속은 별도 현장 검증이 필요합니다.
